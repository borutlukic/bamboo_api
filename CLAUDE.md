This crate exposes the Bamboo DataCenter REST API as a Rust client library.
The code in `src/generated/` is committed to the repo and generated by the `codegen` tool.

To regenerate after spec or fix changes:
```
make generate
```

## Project structure

This is a Cargo workspace with two crates:
- **`.`** (`jira_api`) — the published library crate
- **`codegen/`** — a binary tool that downloads the OpenAPI spec and generates `src/generated/`

## Source Files

### `src/lib.rs`
Re-exports everything from the generated module:
```rust
pub mod generated;
pub use generated::*;
```

### `codegen/src/main.rs`
Downloads the OpenAPI spec if missing, runs analysis with several fixes, then generates code into `src/generated/`. Must be run from the workspace root (which `make generate` and `cargo run -p codegen` both guarantee).

#### Constants
- `BAMBOO_OPENAPI: &str = "openapi/swagger.v3.json"` — local path for the spec (gitignored)
- `BAMBOO_OPENAPI_URL: &str = "https://dac-static.atlassian.com/server/bamboo/swagger.v3.json?_v=1.123.44"` — download URL

#### `download_spec_if_missing()`
- Returns early if the file already exists.
- Creates the `openapi/` directory if needed.
- Downloads using `ureq::get(...).call()`, reads the body into a `String`, writes to `BAMBOO_OPENAPI`.

#### Analysis fixes (applied in this order after `analyzer.analyze()`)

1. **`rename_schema(analysis, "Result", "BuildResult")`**
   Renames the schema named `Result` to `BuildResult` everywhere it appears:
   - Removes the entry from `analysis.schemas`, updates `schema.name`, re-inserts under the new name.
   - For all other schemas: removes/re-inserts in `schema.dependencies`; recurses into `SchemaType::Object` properties via `rename_in_schema_type`.
   - Updates `analysis.dependencies.edges`: renames the key `"Option"` and removes/re-inserts the name from every dependency set.
   - `rename_in_schema_type` handles: `Reference { target }`, `Array { item_type }`, `Union { variants }` (updates `v.target`), `Composition { schemas }` (updates `s.target`), `DiscriminatedUnion { variants }` (updates `v.schema_ref`), `Object { properties }` (recurses into each property's `schema_type`).
   - Also updates `analysis.operations[*].response_schemas` values (plain `String` type names), which the library doesn't rename automatically.

2. **`fix_unused_path_params(analysis)`**
   The Bamboo spec declares some path parameters that are not present in the path template (e.g. `name` on `GET /responsibility/latest/brokenBuild/{planResultKeyOrPlanKey}`, `user` on `DELETE /admin/latest/session/{name}`). The codegen library emits function parameters for them but never uses them, causing `unused variable` compiler warnings. This fix:
   - For each operation, parses `{placeholder}` names from the path template.
   - Retains only `path`-location parameters whose `name` appears in the template; all others are dropped.

#### `GeneratorConfig`
```rust
GeneratorConfig {
    spec_path: PathBuf::from(BAMBOO_OPENAPI),
    output_dir: PathBuf::from("src/generated"),
    module_name: "bamboo_api".to_string(),
    enable_sse_client: false,
    enable_async_client: true,
    tracing_enabled: true,
    ..Default::default()
}
```

#### `main()` sequence
1. `download_spec_if_missing()?`
2. Read and parse the spec as `serde_json::Value`
3. `SchemaAnalyzer::new(spec_value)?.analyze()?`
4. Apply the fixes required
5. Build `GeneratorConfig`, create `CodeGenerator`, call `generate_all(&mut analysis)` then `write_files(&result)`
